## 2. 项目开发总结

本项目围绕“智慧社区服务平台”主题展开，目标是构建一个集居民服务、物业管理和社区互动于一体的综合性系统。项目采用前后端分离架构，前端使用 Vue 3 负责页面与交互，后端使用 Java Servlet 实现业务逻辑与接口服务，数据库使用 MySQL 进行结构化数据存储，并通过 Docker Compose 完成一体化部署。

在功能实现层面，项目已经完成以下核心模块：

- 用户注册登录与角色认证
- 个人中心与资料维护
- 智能报修与服务评价
- 社区活动管理、报名、签到、活动回顾
- 邻里互动发布与管理
- 物业费、停车位、访客登记
- 消息中心与 WebSocket 实时通知

本次二次质检整改中，团队进一步补齐了技术文档、团队报告、个人历史管理列表、页面细节与交互问题，使项目从“功能可运行”提升到“交付材料完整、页面更适合验收展示”的状态。

## 3. 技术难点与解决方案

### 3.1 难点一：多角色权限控制

问题：

- 系统同时面向居民、物业管理员、服务商三个角色，不同角色的可见模块与可执行操作不同。

解决方案：

- 通过 JWT 识别登录用户身份。
- 在后端使用 `RoleAuthorizationFilter` 实现统一权限控制。
- 在前端根据角色动态显示菜单与业务页面入口。

### 3.2 难点二：活动签到二维码安全性

问题：

- 活动签到不能只使用静态二维码，否则容易被截屏滥用。

解决方案：

- 使用 `HmacSHA256` + 日期因子生成动态签到 Token。
- 后端验证签到 Token 是否为当日或前一日有效口令。
- 仅对已报名用户开放签到入口。

### 3.3 难点三：消息通知与实时交互

问题：

- 多个业务动作完成后，需要既保留站内消息记录，又及时提醒当前在线用户。

解决方案：

- 后端在写入 `messages` 表后，调用 WebSocket 推送 `message_created`。
- 前端通过 `/ws/notifications` 接收实时事件并展示通知。
- 本次整改中新增通知去重处理，避免访客登记场景重复提示。

### 3.4 难点四：课程项目交付要求多、文档易缺失

问题：

- 单纯完成代码并不足以通过验收，还需要系统架构、数据库、接口、部署运维、测试与团队报告等完整材料。

解决方案：

- 根据现有实现反向整理正式文档。
- 将文档统一放入 `docs/` 目录，避免交付分散。
- README 增加文档入口，便于教师验收。
